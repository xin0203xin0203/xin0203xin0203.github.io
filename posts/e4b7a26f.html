【ECharts 交互式看板】Hadoop 完全分布式集群搭建详细教程

知安2026-10-302026-10-30

这篇是什么：前三篇已经把集群搭起来、把 MapReduce 跑通、把结果画成静态图。这一篇解决最后一个问题——怎么把结果做成能点、能联动、能当场演示的看板。

产物：一个 9 KB 的单文件 dashboard.html，数据内嵌、双击即开、不依赖服务器。全程只用 Python 标准库 + ECharts，没有 Vue、没有 React、没有构建工具。

系列导航：
① 环境搭建 → ② 数据清洗与 MapReduce → ③ 可视化 → ④ ECharts 交互式看板（本篇）

一、为什么不用 Matplotlib 了

上一篇用 Matplotlib 画了三张静态 PNG，它们能放进报告，但放到网页里就有三个问题：

问题 Matplotlib PNG ECharts 页面
鼠标悬停看数值 ❌ 只能看图 ✅ tooltip 显示精确值
图与图关联 ❌ 三张独立图片 ✅ 点柱子，饼图联动高亮
数据筛选 ❌ 改数据要重画 ✅ JS 里改数组即可
演示时可交互 ❌ 只能放大图片 ✅ 现场点给面试官看
体积 100 KB × 3 张 9 KB（数据内嵌）

这里不写“前端工程”。整件事的核心仍然是数据链路：从 HDFS 取结果 → 转结构化数据 → 渲染。样式和布局是次要的，别把简历写成“前端开发”，写“数据展示页面”最稳。

二、整体架构：为什么数据要内嵌

关键决策：数据内嵌，不做成单独的 .json 文件。

原因是你一定会遇到这个报错：

双击打开 HTML 时协议是 file://，浏览器不允许页面用 fetch 读本地文件（同源策略把每个本地文件都当成独立源）。要绕开只有两条路：起一个 HTTP 服务，或者把数据直接写进 HTML。后者最省事，代价是数据变了要重新生成一次——对 20 行的聚合结果来说完全不是问题。

三、数据准备：把 TSV 变成 JSON

mk_dashboard.py 的前半段只做一件事：读 TSV，产出 JSON 和三个汇总值。

四个细节值得留意：

细节 为什么
encoding="utf-8" 店铺名是中文，不指定会按系统编码读，可能乱码
line.rstrip("\n") 而不是 strip() strip() 会把行尾的空字段也吃掉，字段数就变了
len(parts) != 3 校验 脏行（比如最后一行是空行）直接跳过，不让脏数据进前端
ensure_ascii=False 不写这句中文会变成 \u6570\u7801，文件能跑但没法读

四、页面骨架

三块布局，用 CSS Grid 两列排：

CSS 就三件事，不需要框架：

.panel.full 里的 grid-column: 1 / -1 是 Grid 的写法：从第 1 条网格线跨到最后一条，等于“占满整行”。比 width: 100% 可靠，因为它参与布局计算。

五、三个图的配置要点

5.1 TOP10 横向柱状图

① yAxis.inverse: true：ECharts 的类目轴默认从下往上画，不加 inverse 的话第一名会跑到最底部，图表看起来“反了”。加一行就正过来。

② 数字加千分位：1195069 不如 1,195,069 好读。toLocaleString() 是浏览器内置的，不用引任何数字格式化库。

为什么是横向：店铺名 6–8 个中文字，竖着排会重叠或被迫转 90 度；横向柱状图右边有空间，标签能横着放。这个选择跟数据形态有关，不是审美偏好。

5.2 销售额占比环形图

① radius: ["38%", "62%"]：数组第一项是内半径，第二项是外半径。把内半径设成非 0 就变成环形图，中间空出来正好留给“其他 10 家 49.49%”这类汇总信息。

② TOP10 + 其他合并：

20 个扇区会挤成一圈细缝，标签全重叠。合并成“其他 N 家”之后图才可读——这一步是数据处理，不是美化，报告里能写成“长尾类别合并”。

5.3 销量 vs 销售额散点图

① 数据里的第三位：ECharts 的散点图只认前两位当坐标，第三位可以塞任意自定义字段。这里塞店名，tooltip.formatter 里用 p.data[2] 就能在悬停时显示店铺名——不然你只知道有个点，不知道是谁。

散点图能看出一件柱状图看不出来的事：销量高的店不一定销售额高。如果所有点几乎在一条斜线上，说明客单价接近；如果点散得开，说明店铺的品类结构差异大。我们这个模拟数据里，20 个点会几乎水平排成一条——因为价格是均匀分布，销售额主要由销量决定。

六、联动：点一下就高亮另一个图

这是整个看板的“交互”部分，也是最容易被问的地方。

三个要点：

要点 说明
dispatchAction ECharts 的“外部触发”接口。不用知道图形像素位置，按数据项的 name 就能触发高亮
highlight / downplay 成对使用。高亮后 2.5 秒自动取消，否则会一直亮着，看起来像卡住了
seriesIndex: 0 一个图表里可能有多个 series，必须指明动哪一个

如果没有 dispatchAction，你只能做到“点柱子时自己改 setOption 重画”，那样动画会闪、状态难维护。

七、CDN 挂了怎么办：三级回退

<script src="..."> 有个坑：加载失败不会阻断后续代码，但 echarts 变量就是 undefined，然后整个页面的 JS 全部报错，你只看到一片空白。

我第一版就只引了 jsDelivr 一个，结果在国内环境下经常白屏。

修法是“上一级失败就补下一个”，靠 document.write 同步插入：

为什么用 document.write 而不是动态创建 <script>：document.write 在解析阶段执行是同步阻塞的——写进去的脚本会立刻下载并执行完，再继续往下走。而 appendChild(script) 是异步的，等你后面 echarts.init() 执行时，脚本可能还没加载完，照样报 undefined。

最后再加一层兜底提示，别让用户看白屏：

最稳的做法：把 echarts.min.js（约 1 MB）下载到 dashboard.html 同目录，把最后一级回退指向相对路径 echarts.min.js。这样整个页面零网络依赖，U 盘拷走也能开。

九、问题提问

页面是我写的，但重点不在前端框架。我做的是数据链路：MapReduce 算完结果落在 HDFS，用 getmerge 拉回本地 TSV，Python 脚本把它转成 JSON 内嵌进 HTML，前端用 ECharts 渲染。样式用的是原生 CSS Grid，没有引 Vue 或 React，因为就一个页面，上框架反而重。

问：为什么数据要内嵌，不起个接口？

双击打开时协议是 file://，浏览器同源策略会拦掉 fetch 本地 JSON。要接口就得起服务，那演示成本就高了。数据只有 20 行聚合结果，内嵌最划算。如果数据量大或者要实时刷新，那就该上 Flask + 接口了。

问：图表联动怎么实现的？

ECharts 提供 dispatchAction 接口，可以按数据项的 name 触发 highlight，不用计算像素坐标。点柱状图或表格行，都会调同一个 focusShop 函数，同时高亮柱子和饼图扇区，再把详情写到顶部。高亮 2.5 秒后自动 downplay，否则会一直亮着。

问：遇到最大的坑是什么？

CDN 挂了导致白屏。<script src> 加载失败不会抛异常，只是变量是 undefined，后面 echarts.init() 才报错，看控制台以为是代码问题。后来做了三级回退，用 document.write 同步插入——不能用 appendChild，那个是异步的，等不到脚本加载完。

第三问和第四问是这套东西真正的价值：它证明你不只是“会画图”，而是能定位并解决一个具体的技术问题。

十、常见报错

现象 原因 解法
页面全白，图表区空白 ECharts 没加载 F12 → Console 看 echarts is not defined，加 CDN 回退
Access to fetch ... has been blocked by CORS 用 fetch 读本地 JSON 数据内嵌进 HTML
图表高度 0，什么都不显示 容器没设高度 给 .chart 设 height: 380px
第一名柱子在最底部 类目轴默认方向 yAxis.inverse: true
中文显示成方框 缺字体或编码 HTML <meta charset="utf-8"> + CSS 用中文字体栈
饼图标签重叠成一团 类别太多 只画 TOP 10，其余合并“其他 N 家”
窗口缩放后图表错位 没监听 resize window.addEventListener("resize", () => chart.resize())
表格点行没反应 onclick 绑在了创建之前 先 appendChild 再绑，或者用事件委托
