Hadoop 完全分布式集群搭建详细教程

知安2026-10-292026-10-29

这篇是什么：Windows 上从零搭一套 3 节点（可降 2 节点）完全分布式 Hadoop 集群 的完整记录，每一步都能照着敲。

流程：装 VirtualBox → 装 Ubuntu Server → 配双网卡静态 IP → 克隆三台 → SSH 免密 → 五份配置文件 → 格式化起集群 → 跑通 wordcount。

耗时：首次约 3.5 — 5 小时，建议拆成 2 — 3 次完成；每完成一段做一次快照，出错就回滚，别硬扛。

一、开始前：先花 5 分钟确认硬件

按 Ctrl + Shift + Esc 打开任务管理器，看「性能 → 内存」总量，再确认「CPU」页右下角显示「虚拟化：已启用」。

内存总量 方案 节点分配
16 GB 及以上 3 节点（推荐） master 2G + 2 台 slave 各 1.5G
12 GB 3 节点 master 2G + 2 台 slave 各 1.2G
8 GB 2 节点（仍属完全分布式） master 2G + 1 台 slave 1.5G，副本数设 2
8 GB 以下 不建议跑虚拟机 改用 WSL2 单机伪分布式

如果「虚拟化」显示已禁用，需要进 BIOS 打开 Intel VT-x 或 AMD-V，否则虚拟机根本起不来。磁盘请预留 80 GB 以上空闲空间。

二、下载清单（全部链接）

软件 / 文件 版本 大小 下载地址
VirtualBox（虚拟机） 7.x 约 110 MB virtualbox.org/wiki/Downloads
Ubuntu Server 镜像（官方） 22.04.x LTS 约 2 GB releases.ubuntu.com/22.04
Ubuntu Server 镜像（清华镜像，国内快） 22.04.x LTS 约 2 GB mirrors.tuna.tsinghua.edu.cn
Ubuntu Server 镜像（阿里云镜像） 22.04.x LTS 约 2 GB mirrors.aliyun.com
Hadoop 安装包 3.3.6 约 700 MB archive.apache.org/hadoop-3.3.6
Hadoop 镜像目录（备用） 3.3.x — mirrors.tuna.tsinghua.edu.cn/apache/hadoop
JDK（集群内 apt 安装） OpenJDK 11 — adoptium.net/temurin

镜像选择顺序：先试清华或阿里云镜像（国内 2 — 5 MB/s，2 GB 的 ISO 约 10 分钟），失败再用官方源。Hadoop 3.3.6 在 archive.apache.org 上最稳定，清华镜像里可能已归档。

三、第 1 步：安装 VirtualBox

  • 打开 https://www.virtualbox.org/wiki/Downloads，点 Windows hosts 下载安装包。
  • 双击安装，一路 Next；中途提示安装网络功能驱动时选「安装」。
  • 安装完成后打开 VirtualBox，界面上方能看到「管理 / 工具 / 帮助」菜单，说明可用。

为什么用 VirtualBox 而不是 VMware：VMware 现在要注册 Broadcom 账号才能下载，很多人卡在这一步；VirtualBox 免费、无需注册。已有 VMware 也能照做，第 3 步参数通用，只是「网络设置」里选 NAT + 仅主机。

四、第 2 步：下载 Ubuntu Server 镜像

在下载清单里打开清华镜像目录，找到形如 ubuntu-22.04.x-live-server-amd64.iso 的文件（x 是当前最新小版本，选最大的那个即可），保存到 D 盘或桌面。

一定要选 Server 版（文件名含 live-server），不要 Desktop 版。Desktop 每台多占 600 MB 内存，三台一起开 8 GB 的机器会卡死；而且全程用命令行，用不到桌面。

五、第 3 步：创建第一台虚拟机 hadoop01

VirtualBox → 新建，参数如下：

设置项 值
名称 hadoop01
类型 / 版本 Linux / Ubuntu (64-bit)
内存 2048 MB
处理器 2
硬盘 现在创建虚拟硬盘 → VDI → 动态分配 → 25 GB

创建完成后先不要启动，进入「设置」完成三件事：

  • 网络 → 网卡1：连接方式选 NAT（用于上网、apt 装软件）。
  • 网络 → 网卡2：勾选「启用网络连接」，连接方式选 仅主机（Host-Only）网络（用于集群互通，宿主机浏览器也能访问 9870 页面）。
  • 存储 → 控制器 IDE → 点击光盘图标 → 选择下载好的 ISO 文件。

必须两块网卡。只有 NAT 时，三台虚拟机之间虽然能通，但 IP 每次会变，宿主机也访问不到 9870 页面；只有仅主机时，虚拟机无法上外网装软件。

六、第 4 步：安装 Ubuntu Server

启动 hadoop01，按以下顺序选择（全程键盘操作：Tab / 空格 / 回车）：

  • 语言：English（中文界面在终端里容易乱码，全程英文最稳）。
  • 选择 Install Ubuntu Server。
  • 键盘布局：English (US)。
  • 网络：两块网卡先保持默认 DHCP，不要在这里配静态 IP。
  • 代理地址、镜像源：全部直接回车跳过。
  • 磁盘：Use an entire disk → 选中虚拟磁盘 → Done → 提示格式化选 Continue。
  • 用户设置：Your name 填 hadoop，Server name 填 hadoop01，Username 填 hadoop，密码输两遍。
  • SSH：在「SSH Setup」页面把 Install OpenSSH server 用空格选中（出现 [X]）——这一步不能漏。
  • Featured server snaps：一个都不要选，直接 Done。
  • 等待安装完成 → Reboot Now → 提示移除安装介质时，先在虚拟机「设备 → 光驱」里移除 ISO，再按回车。

重启后输入用户名密码，出现 hadoop@hadoop01:~$ 即为成功。

用户名一定要记牢，它和主机名是两回事：主机名 hadoop01 显示在登录横幅上，但登录要输的是 Username（上面填的 hadoop）。输错会提示 Login incorrect，而且 Linux 不告诉你到底是用户名错还是密码错。

另外，密码输入时屏幕什么都不显示（光标也不动），这是正常的，不是卡住了。密码含数字时用主键盘上排数字键，别用小键盘——虚拟机里 Num Lock 常常不生效，数字会被吞掉。

七、第 5 步：立刻做一个快照

  • 先关机：在虚拟机里执行 sudo poweroff。
  • VirtualBox 管理器 → 右键 hadoop01 → 生成备份（Snapshot），名称填 base-install。

这一步只要半分钟，却能在后面配错时省掉 25 分钟的重装。建议做三次快照：base-install（装完系统）、net-ok（网络配好）、hadoop-ok（集群起来）。出任何问题都先回滚，不要在原机上硬改。

8.1 报错 Device "enp0s8" does not exist 怎么办

这是配网络时最高频的报错，netplan apply 本身不会失败，只是静静跳过那块网卡。先看真实网卡列表：

情况 A：只有 lo 和 enp0s3，没有第二块

说明虚拟机只挂了一块网卡（VirtualBox 里「网卡2」没勾「启用网络连接」）。处理：

关机后 → 设置 → 网络 → 网卡2 → 勾选「启用网络连接」→ 连接方式选「仅主机(Host-Only)网络」→ 确定 → 启动。再执行 ip -br link show，这次会多出一个。

顺带检查宿主机侧：VirtualBox 主界面 → 工具 → 网络 → Host-only Networks，应有一个 vboxnet0，地址 192.168.56.1；没有就点「创建」。

注意：外网通不代表集群通。 网卡1 是 NAT，虚拟机借宿主机上网，ping -c 2 8.8.8.8 能通、apt install 也能用，但它和另外两台虚拟机、和你的 Windows 之间没有固定的互通地址。集群要的是网卡2（仅主机）：三台机器 192.168.56.x 互相通信、Windows 浏览器开 9870 页面，全靠它。所以「能上外网」只证明网卡1 正常，不能据此往下走。

顺序不能反：先让网卡出现，再写 netplan 配置。enp0s8 不存在时，netplan apply 只会跳过这块网卡、不报任何错，配置写得再对也不会生效。

情况 B：第二块网卡叫别的名字（enp0s9 / ens37）

只改名字，其它不动：

netplan apply 前的 WARNING: Cannot call Open vSwitch: ovsdb-server.service is not running 可以忽略，没装 OVS 都会有这句。

ping 的 -c 后面跟的是次数，不是 IP。写成 ping -c 8.8.8.8 会报 ping: invalid argument: '8.8.8.8'；正确写法是 ping -c 2 8.8.8.8（发 2 个包）。验证宿主机链路同理：ping -c 2 192.168.56.1。

8.2 没有 00-installer-config.yaml？关掉 cloud-init 对网络的接管

装完 Ubuntu Server 22.04，进 /etc/netplan 只看到 50-cloud-init.yaml、找不到 00-installer-config.yaml 是正常的：装系统时走的是 cloud-init 流程，配置文件就叫 50-cloud-init.yaml；只有安装时关掉 cloud-init、手动指定网络，才会生成 00-installer-config.yaml。

文件名顺序还有讲究：netplan 按文件名顺序加载，编号小的先生效。继续用 50- 开头，新写的静态 IP 段可能被 cloud-init 的配置压住。所以下面两步要一起做。

Average block replication: 3.0 + Missing replicas: 0 就说明三个节点各存了一份，副本机制真的生效了。第二条把块大小强制为 1 MB，20 MB 的文件会被切成 20 个 block。

十五、第 13 步：跑一次 MapReduce

跑完在 http://192.168.56.101:8088 能看到刚结束的 application，点进去有 map 与 reduce 两个阶段的耗时：

15.1 怎么判断「真的跑成功了」

别只看有没有报错，往下翻作业的计数器（Counters），这几行最有说服力：

看点有三个：

  • Shuffle Errors 全部为 0：说明 map 到 reduce 的数据搬运没有丢失、没有错序。
  • Reduce input records = Reduce output records：每个 key 都完整走完了 reduce，没有被吞。
  • Data-local map tasks = 1：map 任务是在数据所在节点上跑的（数据本地性生效），这是分布式比单机强的地方。

Map output records=1672 → Combine output records=657 这步聚合也很值得讲：combiner 在 map 端先做了一次预聚合，把 1672 条输出压到 657 条，网络传输量直接减少了 60%。

到这里，采集 → 清洗 → 分布式存储 → 分布式计算 这条链路你已经亲手跑通了。接下来才是把自己项目的数据丢进去：用 Hadoop Streaming 统计商品销量 TOP，把结果拉回本地画图，这才是简历上那句「完全分布式」最硬的证据。

十八、术语速查

术语 一句话解释
NameNode 管理文件系统元数据（目录树、块位置映射），不存真实数据
DataNode 实际存数据块的节点，定期向 NameNode 汇报心跳与块列表
SecondaryNameNode 协助合并 edits 与 fsimage，不是 NameNode 的备份
block HDFS 的最小存储单位，默认 128 MB，文件被切成若干块
replication 副本数，完全分布式通常设 3，单节点只能是 1
split MapReduce 的输入分片，通常与一个 block 对应
YARN 资源调度层，ResourceManager 分配资源，NodeManager 管单机
shuffle map 输出按 key 分区排序后交给 reduce 的过程
pseudo-distributed 伪分布式：一台机器跑全部角色，副本只能 1
fully-distributed 完全分布式：多台机器分担角色，副本 3，需 SSH 免密

十九、最终验收清单

  • 三台互 ping 通、互 ssh 免密通（含本机）。
  • hadoop01 的 jps 有 NameNode、DataNode、ResourceManager、NodeManager；hadoop02 有 DataNode、SecondaryNameNode、NodeManager；hadoop03 有 DataNode、NodeManager。
  • 9870 页面 Live Nodes 显示 3，8088 页面 Active Nodes 显示 3。
  • hdfs dfsadmin -report 输出 Live datanodes (3)，三行 Name: 分别是 101 / 102 / 103。
  • fsck 里看到 Average block replication: 3.0 与 Missing replicas: 0（2 节点方案为 2）。
  • 用 1 MB 块大小成功造出多个 block。
  • wordcount 跑成功，part-r-00000 有内容，且计数器里 Shuffle Errors 全为 0。
  • 能说清重启后要重新 start-dfs.sh / start-yarn.sh。
  • 知道 JAVA_HOME 要写进 hadoop-env.sh、启动命令不能多台同时执行。
  • 整个过程写成博客笔记（附命令截图与 fsck 输出）。

跑通数据之后继续下一步：用 10 万条商品数据做一次 Hadoop Streaming 批处理，把结果拉回本地画图——这才是「采集 → 清洗 → 分布式存储 → 可视化」闭环的证据。
