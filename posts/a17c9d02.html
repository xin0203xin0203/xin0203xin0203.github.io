三、清洗到底做了哪三件事

很多简历写”用 Pandas 完成数据清洗”，一问细节就卡壳。这里的三类脏数据是有意埋进去的：

脏数据类型 注入数量 处理方式 判断依据
重复记录 3000 按整行做 set 去重 同店铺同标题同价格视为同一条
缺失值 4000 价格或销量为空直接丢弃 销量是统计口径，缺失无法插补
异常值 3000 price ≤ 0、price > 9999 剔除 -1、0、999999 明显不合业务
类型异常 若干 float() / int() 转换失败即跳过 防止 mapper 阶段崩掉

最终 103001 行 → 93504 行，丢弃 9.2%。这个数字是真实做过的证据，比”完成了数据清洗”有力得多。

别在简历上写”清洗掉 50%”。真实电商数据清洗的丢弃率通常在 5% — 15%，太高说明采集端有问题，面试官会追问你采集逻辑哪里错了。

五、mapper 与 reducer

Hadoop Streaming 的规则很简单：标准输入进、标准输出出。不需要 Java，Python 脚本就能当 Map/Reduce。

5.1 mapper.py

每行输出三列：店铺 \t 销量 \t 单价×销量。

5.2 reducer.py

为什么 reducer 里不需要把数据攒在内存里？ 因为 Hadoop 在 map 和 reduce 之间做了 Shuffle，保证同一个 key 的所有 value 连续送到同一个 reducer，并且按 key 排好序。所以只要”和上一行的店铺比”——一样就累加，不一样就输出上一组。这也是流式处理能处理超大数据的原因。

八、怎么判断它真的跑成功了

只看”有输出文件”不够——空跑也可能生成目录。三个层面一起看：

8.1 作业计数器（最硬）

Map input records 应接近 93503（不含表头），Reduce output records = 20，Shuffle Errors 全 0。

计数器 期望值 说明什么
Map input records ≈ 93503 9 万多条真的进了 mapper
Map output records ≈ 93503 每行都成功解析（有行被跳过就会少）
Reduce input records ≈ 93503 Shuffle 一条没丢
Reduce output records 20 正好 20 个店铺
Shuffle Errors 全 0 网络传输、分区、排序都没问题

8.2 YARN 页面

http://192.168.56.101:8088 → 点进 application_..._0002，能看到 Map / Reduce 各 100% 的进度图，状态 FINISHED。

8.3 输出内容本身

part-00000 有 20 行、每行三列、销售额 与 销量 量级匹配（单价 19 — 2999，销售额 ≈ 销量 × 均价量级）。数目全对才算跑通。

九、面试怎么讲

问：你这个项目是单机还是分布式？

答：Hadoop 部分是 3 节点的完全分布式，1 个 NameNode + 3 个 DataNode，hdfs fsck 能看到 Live_repl=3、副本分布在三台机器上。

问：10 万条数据为什么要用 Hadoop？Pandas 不是更快？

答：对，这 10 万条用单机 Pandas 0.2 秒就能算完，用 Hadoop 反而是浪费时间。我用它是因为要练通整条链路——数据怎么进 HDFS、Mapper 怎么切分、Shuffle 怎么按 key 归并、Reduce 怎么聚合，这套东西在数据量到几百 GB 时才有性能优势。我的重点是掌握链路和原理，不是拿 10 万条去证明 Hadoop 快。

问：你的文件在 HDFS 里切成几块？

答：1 块。数据只有 7.8 MB，远小于 128 MB 的默认块大小，所以不切分。如果数据是 500 MB，就会切成 4 块（128+128+128+116），每块一个 Map 任务，并行度由块数决定。

问：清洗阶段丢了哪些数据？丢了多少？

答：三类——重复记录、缺失值、价格异常值，103001 行清洗后 93504 行，丢弃 9.2%。重复按整行判重，缺失按价格或销量为空直接丢弃，异常是价格 ≤0 或 >9999，包括采集时页面渲染错位导致的 -1、999999。

十、常见报错

报错 原因 解法
Output directory /data/products/shoptop already exists 上次结果还在 hdfs dfs -rm -r /data/products/shoptop
No such file or directory: mapper.py 没加 -files 命令里补 -files mapper.py,reducer.py
Permission denied: mapper.py 脚本没执行权限 用 -mapper "python3 mapper.py"，别直接当可执行文件
python3: command not found 节点上没有 python3 sudo apt install -y python3（三台）
reducer 输出 0 行 mapper 输出的分隔符与 reducer 的 split("\t") 不一致 统一用 \t，别混空格
中文变乱码 CSV 编码不是 UTF-8 生成时用 encoding="utf-8"，读时也加

十一、下一步

跑完这一节，链路只差最后一段——可视化：

  1. 把 shop_top.tsv 拉回本地，用 Matplotlib/Seaborn 画销量 TOP 10 柱状图、品类占比饼图；
  2. 或者用 ECharts 做交互式看板，配 HTML+CSS 静态页面；
  3. 再补一个对比实验：同一份数据，Hadoop Streaming 耗时 vs 单机 Pandas 耗时——这个数据面试时非常有用。

一句话总结这两篇：第一篇把 3 节点集群从零搭起来并跑通 wordcount，第二篇用自己的 10 万条数据跑通 MapReduce 并拿到业务结果。合起来就是”采集 → 清洗 → 分布式存储 → 分布式计算”的完整闭环。
